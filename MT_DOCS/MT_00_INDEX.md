## 1. Структура документации [MT]

Для каждого мода — **2 файла** в `MT_MODS/<имя>/`:
1. **`README.md`** — лицо мода: фичи, механики, **TODO в конце**. Правила кода — не здесь.
2. **`DATABASE.md`** — техническая база: архитектура, специфичные грабли, ссылки на `MT_02`/`MT_03`/`MT_04`.

Общие правила (не дублируются в модах):
- `MT_01_AI_PROTOCOL` — как работает ИИ (процесс)
- `MT_02_RULES` — §1 факты движка / §2 соглашения проекта
- `MT_03_KNOWLEDGE` — §1 симптомы / §2 факты API / §3 паттерны
- `MT_04_NAVIGATION` — декомпил + cheat sheet + чек-листы
- `CHANGELOG` — единственная история изменений проекта

## 4. Правило «один факт — одно место»

Каждый факт имеет **канонический адрес**:
- Факты о движке → `MT_02_RULES` §1
- Соглашения проекта → `MT_02_RULES` §2
- Симптомы багов → `MT_03_KNOWLEDGE` §1
- Подтверждённые API (с file:line) → `MT_03_KNOWLEDGE` §2
- Паттерны (проверенные рецепты) → `MT_03_KNOWLEDGE` §3
- Пути в декомпиле → `MT_04_NAVIGATION` §1–§3
- Чек-листы задач → `MT_04_NAVIGATION` §4
- Протокол работы → `MT_01_AI_PROTOCOL` §1
- История изменений → `CHANGELOG`

**Если факт встречается второй раз — это ссылка, не копия.** Если хочется скопировать — значит, факт принадлежит не туда, где ты его пишешь.

## 5. Пометки статусов

- `[ ]` не начато · `[~]` в работе · `[x]` готово · `[!]` заблокировано · `[?]` под вопросом
- `[MT]` — префикс проекта · `mtmw:` — тег предмета (нижний регистр)
- **Критично** — ломает игру / данные
- **Костыль** — работает, но некрасиво
- **НЕ ПРОВЕРЕНО** — нет теста
- **Не убирать** — критично для B42.21

# CHANGELOG — проект [MT]

> **Единственная история изменений проекта.** Не дублируется в файлах.
> **Правило:** сюда — **крупные вехи**, не per-file diff. Мелкие правки — `git log -- MT_DOCS/<файл>`.
>
> **Что считается вехой:**
> - Новая структура доков, новые корневые файлы, удаление файлов.
> - Новый мод в `MT_MODS/`, удаление мода.
> - Смена канона (правило переехало из `MT_03` в `MT_02`, факт стал соглашением и т.п.).
> - Крупный фикс, который меняет несколько файлов.
> - Переход на новую версию игры / новый декомпил.
>
> **Что НЕ пишем:**
> - «Добавил 3 строки в §1.2» — это diff, есть в git.
> - «Поправил опечатку».
> - «Обновил версию Changelog».

## Как пополнять

1. **Крупная веха** — новая секция `### YYYY-MM-DD — краткое название`.
2. Внутри — 2–5 строк «что и почему».
3. **Не** описывать diff (это git).
4. Дата — реальная. Версии (`v3.0`, `v3.1`) — вспомогательны для кросс-ссылок, но не обязательны.
